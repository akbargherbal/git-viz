# Repository Evolution Datasets - Usage Guide

## Overview

This guide describes the datasets generated by the Repository Evolution Analyzer when run with the `--preset full` option. Each dataset serves a specific analytical purpose and is optimized for different visualization and analysis scenarios.

**Command used:**
```bash
python strata.py ../some-repo/ -o DATASETS/output --preset full
```

## Core Datasets

### file_lifecycle.json

**Location:** `DATASETS/output/file_lifecycle.json`

#### Overview
The foundational dataset containing the complete commit-by-commit evolution of every file in the repository. This is the most detailed and comprehensive dataset, tracking each file from creation through modifications to deletion.

#### Purpose
- Track complete file history across all commits
- Understand file evolution patterns and lifecycle stages
- Analyze code churn and stability
- Identify high-change and high-risk files

#### Key Metrics

**File-level:**
- `path` - Full file path
- `created_at` - ISO timestamp of file creation
- `deleted_at` - ISO timestamp of deletion (null if active)
- `total_commits` - Number of commits affecting this file
- `authors` - List of unique contributors
- `lines_added` - Cumulative lines added
- `lines_deleted` - Cumulative lines deleted
- `net_lines` - Net change (added - deleted)
- `age_days` - File age in days
- `is_active` - Boolean indicating if file still exists

**Commit-level (per file):**
- `commit_hash` - Git commit SHA
- `timestamp` - ISO datetime with timezone
- `author` - Commit author name
- `author_email` - Author email address
- `author_id` - Normalized author identifier
- `author_domain` - Email domain (e.g., company.com)
- `message` - Commit message
- `diff_added` - Lines added in this commit
- `diff_deleted` - Lines deleted in this commit
- `sequence` - Commit number for this file (0-based)
- `is_first_commit` - Boolean flag
- `is_last_commit` - Boolean flag
- **Temporal labels:**
  - `year`, `quarter`, `month`
  - `week_no` - ISO week number
  - `day_of_week` - 0=Monday, 6=Sunday
  - `day_of_year` - Day number (1-365/366)

#### Use Cases

1. **Code Archaeology**
   - Trace why and when specific code was added
   - Find the original author of any code section
   - Understand the historical context of changes

2. **Risk Assessment**
   - Identify files with high churn (unstable code)
   - Find files that haven't been touched in years (abandoned code)
   - Detect files with many authors (coordination complexity)

3. **Onboarding Analysis**
   - Show new team members the evolution of key files
   - Identify which files are actively maintained vs legacy
   - Understand team contribution patterns

4. **Technical Debt Tracking**
   - Find files with repeated bug fixes (search commit messages)
   - Identify refactoring candidates (high churn + many authors)
   - Track deletion of deprecated code

#### Query Examples

```javascript
// Find files with most commits
const mostChanged = files
  .sort((a, b) => b.total_commits - a.total_commits)
  .slice(0, 10);

// Find files deleted in the last 6 months
const recentlyDeleted = files
  .filter(f => f.deleted_at && 
    new Date(f.deleted_at) > sixMonthsAgo);

// Calculate average file age
const avgAge = files
  .filter(f => f.is_active)
  .reduce((sum, f) => sum + f.age_days, 0) / activeFiles.length;

// Find files touched by specific author
const authorFiles = files
  .filter(f => f.authors.includes("john_doe"));
```

## Metadata

### file_index.json

**Location:** `DATASETS/output/metadata/file_index.json`

#### Overview
A fast-lookup index of all files with current state information and summary statistics. Optimized for quick searches and filtering without loading the full lifecycle data.

#### Purpose
- Enable fast file lookups by path or pattern
- Provide current state snapshot (active vs deleted)
- Offer summary statistics without processing full history
- Support file browser and search interfaces

#### Key Metrics

**Per file:**
- `path` - File path
- `extension` - File extension (e.g., ".py", ".js")
- `created_at` - Creation timestamp
- `deleted_at` - Deletion timestamp (null if active)
- `is_active` - Current existence status
- `total_commits` - Total number of commits
- `unique_authors` - Number of different contributors
- `first_commit_hash` - SHA of creation commit
- `last_commit_hash` - SHA of most recent commit
- `age_days` - Age in days
- `lines_added` - Total lines added over lifetime
- `lines_deleted` - Total lines deleted
- `net_lines` - Current size estimate (added - deleted)

#### Use Cases

1. **File Browser/Explorer**
   - Build a searchable file tree
   - Filter by file type, age, or activity status
   - Show summary cards for files

2. **Quick Statistics**
   - "How many Python files exist?"
   - "What's the average file age?"
   - "Which files have the most contributors?"

3. **File Search**
   - Find all files matching a pattern
   - Locate files by extension or directory
   - Filter by activity status (active/deleted)

4. **Dashboard Widgets**
   - Show total file counts by type
   - Display newest/oldest files
   - Highlight most collaborative files

#### Query Examples

```javascript
// Count files by extension
const byExtension = fileIndex.reduce((acc, file) => {
  acc[file.extension] = (acc[file.extension] || 0) + 1;
  return acc;
}, {});

// Find recently created files (last 30 days)
const recent = fileIndex
  .filter(f => {
    const age = (Date.now() - new Date(f.created_at)) / (1000*60*60*24);
    return age <= 30;
  });

// Find orphaned files (1 author, no recent activity)
const orphaned = fileIndex
  .filter(f => f.is_active && 
    f.unique_authors === 1 && 
    f.age_days > 365);
```

## Temporal Aggregations

### temporal_daily.json

**Location:** `DATASETS/output/aggregations/temporal_daily.json`

#### Overview
Day-by-day aggregation of repository activity, showing commits, files changed, authors active, and line changes for each calendar day.

#### Purpose
- Visualize repository activity over time
- Identify busy vs quiet periods
- Detect trends and patterns in development velocity
- Understand team work rhythms

#### Key Metrics

**Per day:**
- `date` - ISO date (YYYY-MM-DD)
- `year`, `month`, `day` - Separated date components
- `day_of_week` - 0=Monday, 6=Sunday
- `commits` - Number of commits on this day
- `files_changed` - Unique files modified
- `authors` - List of active author IDs
- `author_count` - Number of unique authors
- `lines_added` - Total lines added
- `lines_deleted` - Total lines deleted
- `net_lines` - Net change (added - deleted)

#### Use Cases

1. **Activity Timeline**
   - Create line charts of commits over time
   - Show coding velocity trends
   - Identify release cycles and sprints

2. **Team Rhythm Analysis**
   - Detect crunch periods (high commit days)
   - Find work pattern anomalies
   - Understand weekday vs weekend activity

3. **Productivity Metrics**
   - Track team throughput over time
   - Measure sprint-to-sprint changes
   - Correlate activity with external events

4. **Calendar Heatmaps**
   - Build GitHub-style contribution calendars
   - Visualize work intensity by day of week
   - Show seasonal patterns

#### Query Examples

```javascript
// Find the busiest day ever
const busiestDay = dailyData
  .reduce((max, day) => 
    day.commits > max.commits ? day : max
  );

// Calculate average commits per weekday
const weekdayAvg = dailyData
  .filter(d => d.day_of_week < 5) // Mon-Fri
  .reduce((sum, d) => sum + d.commits, 0) / workdays.length;

// Identify quiet periods (no commits for 7+ days)
const quietPeriods = findGaps(dailyData, 7);

// Monthly velocity trend
const monthlyTrend = groupByMonth(dailyData)
  .map(month => ({
    month: month.key,
    avgCommitsPerDay: month.totalCommits / month.days
  }));
```

#### Use Cases

#### Query Examples

```javascript
// Year-over-year growth
const yoyGrowth = monthlyData
  .filter(m => m.year === currentYear)
  .reduce((sum, m) => sum + m.commits, 0) / 
  monthlyData
    .filter(m => m.year === currentYear - 1)
    .reduce((sum, m) => sum + m.commits, 0);

const byQuarter = groupByQuarter(monthlyData);
const topQuarter = Object.entries(byQuarter)

// Calculate churn rate (files deleted / created)
const churnRate = monthlyData.map(m => ({
  month: m.year_month,
  churn: m.files_deleted / m.files_created
}));
```

## Directory Analysis

### directory_stats.json

**Location:** `DATASETS/output/aggregations/directory_stats.json`

#### Overview
Hierarchical statistics for every directory in the repository, showing file counts, activity levels, and author distribution.

#### Purpose
- Understand repository structure
- Identify hotspots of activity
- Compare different modules/components
- Guide refactoring efforts

#### Key Metrics

**Per directory:**
- `path` - Directory path (e.g., "src/components")
- `depth` - Nesting level (0 = root)
- `file_count` - Total files in directory (not recursive)
- `active_files` - Currently existing files
- `deleted_files` - Removed files
- `total_commits` - All commits touching this directory
- `unique_authors` - Different contributors
- `lines_added` - Total lines added
- `lines_deleted` - Total lines deleted
- `net_lines` - Current estimated size
- `created_at` - When first file was added
- `last_modified` - Most recent commit timestamp
- `age_days` - Directory age
- `subdirectories` - List of immediate children

#### Use Cases

1. **Architecture Visualization**
   - Build treemaps of repository structure
   - Show relative sizes and activity by module
   - Identify bloated or neglected areas

2. **Ownership Mapping**
   - Determine which teams own which directories
   - Find areas with too many contributors (coordination issues)
   - Identify single-owner risk areas

3. **Refactoring Targets**
   - Find directories with high churn
   - Locate large, monolithic modules
   - Identify candidates for splitting or cleanup

4. **Onboarding**
   - Show new developers where activity is concentrated
   - Explain repository organization
   - Highlight stable vs volatile areas

#### Query Examples

```javascript
// Find largest directories by file count
const largest = directoryStats
  .sort((a, b) => b.file_count - a.file_count)
  .slice(0, 10);

// Calculate average files per directory by depth
const avgByDepth = groupByDepth(directoryStats)
  .map(group => ({
    depth: group.depth,
    avgFiles: group.total_files / group.count
  }));

// Find most active directories (commits per day)
const mostActive = directoryStats
  .map(d => ({
    ...d,
    commitsPerDay: d.total_commits / d.age_days
  }))
  .sort((a, b) => b.commitsPerDay - a.commitsPerDay);

// Identify orphaned directories (no activity in 1+ year)
const stale = directoryStats
  .filter(d => {
    const daysSinceChange = 
      (Date.now() - new Date(d.last_modified)) / (1000*60*60*24);
    return daysSinceChange > 365;
  });
```

## Network Analysis

### author_network.json

**Location:** `DATASETS/output/networks/author_network.json`

#### Overview
A collaboration network showing which authors work together, built from shared file modifications. Represents the social structure of the development team.

#### Purpose
- Visualize team collaboration patterns
- Identify knowledge silos and bottlenecks
- Understand team structure and communication needs
- Detect isolated contributors

#### Key Metrics

**Nodes (authors):**
- `id` - Author identifier (normalized)
- `name` - Display name
- `email` - Email address
- `domain` - Email domain
- `commits` - Total commits by this author
- `files_touched` - Unique files modified
- `lines_added` - Total lines added
- `lines_deleted` - Total lines deleted
- `first_commit` - Earliest contribution timestamp
- `last_commit` - Most recent contribution timestamp
- `active_days` - Days between first and last commit

**Edges (collaborations):**
- `source` - First author ID
- `target` - Second author ID
- `weight` - Collaboration strength (shared files)
- `shared_files` - List of files both authors modified
- `commits_a` - Source author's commits on shared files
- `commits_b` - Target author's commits on shared files

#### Use Cases

1. **Team Visualization**
   - Create force-directed network graphs
   - Show who works with whom
   - Identify team clusters and sub-groups

2. **Knowledge Transfer**
   - Find mentorship opportunities (senior + junior pairs)
   - Identify experts for specific files
   - Plan pair programming sessions

3. **Organizational Analysis**
   - Detect silos (disconnected author groups)
   - Find bridge people connecting teams
   - Understand communication needs

4. **Onboarding Support**
   - Assign mentors based on file overlap
   - Identify who to ask about specific code
   - Map out team social structure

#### Query Examples

```javascript
// Find most collaborative author
const mostConnected = nodes
  .map(author => ({
    ...author,
    connections: edges.filter(e => 
      e.source === author.id || e.target === author.id
    ).length
  }))
  .sort((a, b) => b.connections - a.connections)[0];

// Identify knowledge silos (authors with few connections)
const isolated = nodes.filter(author => {
  const connections = edges.filter(e =>
    e.source === author.id || e.target === author.id
  );
  return connections.length <= 2;
});

// Find strongest collaborations
const strongestPairs = edges
  .sort((a, b) => b.weight - a.weight)
  .slice(0, 5);

// Calculate network density
const maxEdges = (nodes.length * (nodes.length - 1)) / 2;
const density = edges.length / maxEdges;
```

### cochange_network.json

**Location:** `DATASETS/output/networks/cochange_network.json`

#### Overview
A file coupling network showing which files are frequently modified together in the same commits. Reveals logical dependencies and hidden coupling.

#### Purpose
- Discover architectural dependencies not in code
- Identify tightly coupled modules
- Find refactoring candidates
- Understand ripple effects of changes

#### Key Metrics

**Nodes (files):**
- `id` - File path
- `commits` - Total commits to this file
- `authors` - Number of different contributors
- `lines_added` - Cumulative additions
- `lines_deleted` - Cumulative deletions
- `age_days` - File age
- `is_active` - Still exists

**Edges (co-changes):**
- `source` - First file path
- `target` - Second file path
- `weight` - Number of commits changing both files
- `confidence` - Strength of coupling (0-1)
  - `weight / min(source.commits, target.commits)`
- `shared_commits` - List of commit hashes affecting both
- `shared_authors` - Authors who changed both files

#### Use Cases

1. **Architectural Understanding**
   - Visualize actual file dependencies
   - Find clusters of related files
   - Identify architectural boundaries

2. **Refactoring Planning**
   - Find files that should be merged (high co-change)
   - Identify modules that should be split
   - Detect circular dependencies

3. **Impact Analysis**
   - Predict which files will need changes together
   - Estimate scope of feature work
   - Plan testing strategies

4. **Code Review**
   - Check if related files were updated
   - Verify consistency across coupled files
   - Catch incomplete changes

#### Query Examples

```javascript
// Find most coupled file pairs
const tightestCoupling = edges
  .sort((a, b) => b.confidence - a.confidence)
  .slice(0, 10);

// Identify hub files (coupled to many others)
const hubs = nodes.map(file => ({
  ...file,
  couplings: edges.filter(e =>
    e.source === file.id || e.target === file.id
  ).length
}))
.sort((a, b) => b.couplings - a.couplings);

// Find orphan files (no co-changes)
const orphans = nodes.filter(file => {
  return !edges.some(e =>
    e.source === file.id || e.target === file.id
  );
});

// Calculate ripple effect score
const rippleEffect = (filePath) => {
  const connections = edges.filter(e =>
    e.source === filePath || e.target === filePath
  );
  return connections.reduce((sum, e) => sum + e.weight, 0);
};
```

## Milestones

### release_snapshots.json

**Location:** `DATASETS/output/milestones/release_snapshots.json`

#### Overview
Snapshots of repository state at each tagged release, showing file counts, contributor stats, and size metrics at milestone points.

#### Purpose
- Track repository evolution at release boundaries
- Compare releases for planning
- Document project growth milestones
- Support release notes and changelogs

#### Key Metrics

**Per release:**
- `tag` - Git tag name (e.g., "v1.2.0")
- `commit_hash` - SHA of release commit
- `timestamp` - Release date
- `files` - File snapshot at this release
  - `total` - Total files in repo
  - `by_extension` - Count per file type
  - `active` - Existing files
  - `created_since_last` - New files since previous release
  - `deleted_since_last` - Removed files
- `contributors` - Author statistics
  - `total` - All-time unique contributors
  - `active_in_release` - Contributors this release
  - `new_contributors` - First-time contributors
- `size` - Size metrics
  - `lines_added` - Total additions to date
  - `lines_deleted` - Total deletions
  - `net_lines` - Estimated current size
- `commits_since_last` - Commits between this and previous release
- `days_since_last` - Release interval

#### Use Cases

1. **Release Planning**
   - Estimate release cadence
   - Plan feature scope based on historical data
   - Set realistic timelines

2. **Changelog Generation**
   - Identify what changed between releases
   - Highlight new contributors
   - Show file statistics

3. **Growth Tracking**
   - Visualize project growth over versions
   - Show team expansion
   - Track codebase size evolution

4. **Quality Metrics**
   - Compare code churn between releases
   - Identify stable vs unstable releases
   - Track contributor diversity

#### Query Examples

```javascript
// Calculate average release interval
const avgDays = snapshots
  .slice(1) // Skip first release
  .reduce((sum, r) => sum + r.days_since_last, 0) / 
  (snapshots.length - 1);

// Find releases with most new files
const biggestReleases = snapshots
  .sort((a, b) => 
    b.files.created_since_last - a.files.created_since_last
  );

// Track contributor growth
const contributorGrowth = snapshots.map(r => ({
  release: r.tag,
  total: r.contributors.total,
  new: r.contributors.new_contributors
}));

// Identify major releases (>100 commits)
const majorReleases = snapshots
  .filter(r => r.commits_since_last > 100);
```

## Frontend-Optimized Datasets

### project_hierarchy.json

**Location:** `DATASETS/output/frontend/project_hierarchy.json`

#### Overview
A hierarchical tree structure optimized for treemap visualizations, with health scoring and metrics at each node. Pre-computed for fast rendering.

#### Purpose
- Power interactive treemap visualizations
- Enable drill-down exploration of repository structure
- Show health metrics visually
- Support dashboard displays

#### Key Metrics

**Tree structure:**
- `name` - Directory or file name
- `path` - Full path
- `type` - "directory" or "file"
- `children` - Array of child nodes (for directories)
- `size` - Metric for sizing (total_commits or net_lines)
- `value` - Same as size (for compatibility)

**Health metrics:**
- `health_score` - Overall health (0-100)
  - Based on: recency, author diversity, stability
- `recency_score` - How recently modified (0-100)
- `stability_score` - Churn vs age ratio (0-100)
- `ownership_score` - Author distribution (0-100)

**Activity metrics:**
- `total_commits` - Commits to this node
- `unique_authors` - Contributor count
- `lines_added` - Total additions
- `lines_deleted` - Total deletions
- `net_lines` - Current size estimate
- `last_modified` - Most recent commit timestamp
- `age_days` - Age in days

#### Use Cases

1. **Interactive Treemap Explorer**
   - Render zoomable treemap
   - Color by health score
   - Size by commits or lines of code
   - Click to drill down

2. **Health Dashboard**
   - Show overall project health
   - Highlight problematic areas (red zones)
   - Track health trends over time

3. **Code Review Prioritization**
   - Focus on low-health areas
   - Identify files needing attention
   - Balance review effort

4. **Team Allocation**
   - See which areas need more resources
   - Identify over/under-staffed modules
   - Plan capacity

#### Rendering Example

```javascript
// D3.js treemap example
const treemap = d3.treemap()
  .size([width, height])
  .paddingInner(2);

const root = d3.hierarchy(projectHierarchy)
  .sum(d => d.type === 'file' ? d.total_commits : 0);

treemap(root);

// Color by health
const colorScale = d3.scaleLinear()
  .domain([0, 50, 100])
  .range(['#d73027', '#fee08b', '#1a9850']);

root.leaves().forEach(node => {
  const color = colorScale(node.data.health_score);
  // render rectangle with color
});
```

A comprehensive file-by-file metrics table with coupling analysis, optimized for detail panels and search interfaces.

#### Purpose

- Provide coupling information
- Support file search and discovery

#### Key Metrics

**Per file:**
- `path` - File path
- `extension` - File type
- `is_active` - Currently exists

**Lifecycle:**
- `created_at` - Creation timestamp

- `author_list` - Array of author IDs
- `lines_added` - Cumulative additions
- `lines_deleted` - Cumulative deletions

**Coupling:**

  - `path` - Coupled file path

- `max_coupling_strength` - Strongest coupling value

**Computed metrics:**
- `churn_rate` - (added + deleted) / total_commits

#### Use Cases

1. **File Detail Panel**

2. **File Browser**

3. **Dependency Discovery**

   - Plan refactoring scope

4. **Risk Assessment**
   - Highlight high-churn files
   - Find files with single owner
   - Identify large, complex files

#### Query Examples

```javascript
// Create sortable table
const table = new DataTable(fileMetricsIndex, {
  columns: [
```

## Tips & Best Practices

### Performance Optimization

1. **Lazy load large datasets**
   - Load only what's needed for current view
   - Use pagination for file lists
   - Stream large JSONs when possible

2. **Cache loaded data**
   ```javascript
   const cache = new Map();
   
   async function loadDataset(name) {
     if (cache.has(name)) return cache.get(name);
     const data = await fetch(`datasets/${name}`).then(r => r.json());
     cache.set(name, data);
     return data;
   }
   ```

3. **Use indexes for lookups**
   ```javascript
   // Create lookup indexes
   const fileById = new Map(
     fileIndex.map(f => [f.path, f])
   );
   
   const authorById = new Map(
     authorNetwork.nodes.map(a => [a.id, a])
   );
   ```

### Data Validation

Always check the manifest first:
```javascript
const manifest = await loadManifest();

// Check schema version compatibility
if (manifest.schema_version !== '1.1.0') {
  console.warn('Schema version mismatch - some features may not work');
}

// Check which datasets are available
if (!manifest.datasets.author_network) {
  console.log('Author network not available - analysis was run without phase2');
}
```

### Error Handling

```javascript
async function safeLoadDataset(path, fallback = null) {
  try {
    const response = await fetch(path);
    if (!response.ok) return fallback;
    return await response.json();
  } catch (error) {
    console.error(`Failed to load ${path}:`, error);
    return fallback;
  }
}

// Use fallbacks gracefully
const fileIndex = await safeLoadDataset('metadata/file_index.json', []);
if (fileIndex.length === 0) {
  showMessage('File index not available');
}
```

- A: Parse with `new Date(timestamp)` and display in user's local time
