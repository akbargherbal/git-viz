Import/Module Management
Beginner 
import * as d3 from "d3";

What

Imports all exports from d3 library and binds them to a namespace object named 'd3'

Why

D3 has many exports (selection methods, scales, shapes, etc.) and using namespace import allows accessing all of them through a single object (d3.select, d3.scaleLinear, etc.). This is the conventional way to import D3 as it maintains the familiar API structure and avoids naming conflicts.

How

The 'import * as' syntax creates a module namespace object containing all named exports from the module. Every export becomes a property of the namespace object.

Context

Used to access D3's selection and DOM manipulation methods for rendering coupling arcs and managing SVG elements in the treemap visualization.

Alternatives

Named imports for specific functions 'import { select, arc } from "d3"'; default import if d3 exported one; importing sub-packages like 'import { select } from "d3-selection"'

What

Why

Short-circuit evaluation prevents accessing properties of null/undefined. First condition checks if selectedFile exists, second condition only evaluates if first is truthy. Prevents runtime errors.

How

Logical AND (&&) returns first falsy value or last value if all truthy. If selectedFile is null/undefined, expression short-circuits and returns falsy without evaluating second part.

Context
