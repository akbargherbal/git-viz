Import/Module Management
Intermediate 
import { render, screen, createEnrichedFile } from "@/test-utils";

What

Import statement using '@/' path alias to reference test utilities from project root

Why

Provides consistent, absolute-style imports that avoid brittle relative paths like '../../../test-utils'. Makes test files easier to refactor and move without breaking imports. Improves readability by clearly indicating imports come from project root.

How

Configured in tsconfig.json paths mapping and build tool (Vite/Webpack) resolve.alias. The '@/' prefix is resolved to the project's src directory or configured base path.

Context

Importing test utilities (render, screen) and test data factory (createEnrichedFile) from centralized test-utils module. These are shared testing helpers used across all test files.

Alternatives

Relative imports like '../../../../test-utils'; different alias conventions like '~/' or 'src/'; Node.js package.json imports field; no alias with full relative paths

CouplingView.test.tsx

What

Naming convention for test files using .test.tsx suffix

Why

Standard convention that makes test files easily identifiable. Test runners automatically discover files matching this pattern. Clearly associates test with component being tested.

How

File name matches component name (CouplingView) with .test suffix before extension. Test runners use glob patterns like **/*.test.tsx to find tests.

Context

Test file for CouplingView component follows convention: CouplingView.test.tsx. Located in __tests__ directory alongside component.

Alternatives

CONCEPT-039

React/JSX Syntax
Beginner 
couplingThreshold={0.3}

What

Passing numeric literal as prop value using curly braces

Why

Numbers must be passed in curly braces in JSX (not as strings). Ensures type safety - component receives actual number, not string. Allows numeric operations without parsing.

How

Curly braces indicate JavaScript expression. Numeric literal 0.3 is evaluated and passed as number type to component.

Context

Passing threshold value 0.3 as number to CouplingView component. Different tests use different threshold values (0.3, 0.5) to test filtering behavior.

Alternatives

String prop "0.3" (wrong type); variable containing number; computed expression; constant reference
