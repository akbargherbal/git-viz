Import/Module Management
Beginner 
import React, { useMemo } from "react";

What

Combines default import of React namespace with named import of specific hook (useMemo) in a single statement

Why

Efficiently imports both React (needed for JSX transformation) and the specific hook used in the component. This pattern reduces import statements while clearly documenting which React features are utilized. The useMemo hook is explicitly imported for performance optimization of computed values.

How

ES6 module syntax allows mixing default and named imports from the same module. The default import (React) comes first, followed by curly braces containing named imports. The TypeScript/Babel compiler transforms JSX using the React namespace.

Context

Used to access React for JSX and the useMemo hook for memoizing the sorted/sliced topDirectories array computation

Alternatives

Separate import statements; namespace import 'import * as React from "react"'; importing hooks individually; using React.useMemo without destructuring

React/Performance Optimization
Intermediate 
const topDirectories = useMemo(() => {
    return directories
      .sort((a, b) => b.activity_score - a.activity_score)
      .slice(0, Math.min(50, directories.length));
  }, [directories]);

What

React hook that memoizes the result of an expensive computation (sorting and slicing directories array) and only recalculates when dependencies change

Why

Prevents unnecessary re-sorting of directories array on every render. Sorting is O(n log n) operation that would run on every render without memoization. Improves performance especially with large directory lists. Only recalculates when directories array reference changes. Reduces wasted CPU cycles and improves component responsiveness.

How

useMemo accepts two arguments: a function that returns the computed value, and a dependency array. React caches the returned value and only re-runs the function when dependencies change. Returns the cached value on subsequent renders if dependencies haven't changed.

Context

Memoizes the sorted and sliced top 50 directories for the exclusion UI. The computation involves sorting by activity_score (descending) and taking first 50 items. Only recalculates when directories prop changes.

Alternatives

Calculate in render without memoization (performance cost); useMemo with additional dependencies; separate state with useEffect; compute in parent component; use external memoization library

Tags

What

Array slice method combined with Math.min to safely extract first N elements without exceeding array length

Why

Limits displayed directories to top 50 while handling edge case where array has fewer than 50 items. Math.min prevents slice from requesting more items than exist. Avoids potential issues with slice receiving end index larger than array length (though slice handles this gracefully). Makes intent explicit and defensive.

How

Array.slice(start, end) extracts elements from start index to end index (exclusive). Math.min(50, directories.length) returns smaller of 50 or actual array length. This ensures end index never exceeds array bounds. Slice returns new array without mutating original.

Context

Takes first 50 directories from sorted array for display in exclusion UI. Comment indicates showing top 50 for exclusion even though fewer might be displayed in main visualization.

Alternatives

What

Dependency array for useMemo hook that specifies when the memoized value should be recalculated

Why

Controls when expensive computation re-runs. Only recalculates when directories array reference changes. Prevents unnecessary recalculations on unrelated state changes. Essential for useMemo to work correctly - without it, would recalculate every render (defeating purpose) or never recalculate (stale data).

How

React compares each dependency value between renders using Object.is() equality. If any dependency changes, the memoization function re-runs. If all dependencies are unchanged, cached value is returned. Empty array would memoize forever; no array would recalculate every render.

Context

Specifies that topDirectories should only be recalculated when the directories prop changes. Since sorting/slicing only depends on directories data, this is the only necessary dependency.

Alternatives

Multiple dependencies [directories, otherValue]; empty array [] (never recalculate); no array (always recalculate); exhaustive dependencies including all referenced values
