CONCEPT-005

TypeScript Type System
Intermediate 
phase: "metadata" | "tree" | "activity" | "complete";

What

Type annotation using union of specific string literal types, restricting the property to exactly one of the specified string values

Why

Provides type-safe enumeration without runtime overhead; enables exhaustive checking in switch statements; better autocomplete than plain strings; self-documenting - shows all valid values; prevents typos and invalid values; more flexible than enums (can be used in type positions); no need for enum declaration

How

The pipe operator (|) creates a union type; string literals in quotes become specific types; TypeScript narrows the type to exactly these four strings; any other string value will cause a compile error; works with type narrowing and control flow analysis

Context

Defines the four valid phases of data loading: metadata (loading metadata), tree (loading tree structure), activity (loading activity data), and complete (loading finished). This creates a state machine for progress tracking.

Alternatives

Enum (enum Phase { Metadata = "metadata", ... }); const assertion with array (const phases = ["metadata", ...] as const; type Phase = typeof phases[number]); plain string type (less safe); numeric enum; separate boolean flags; state machine library

CONCEPT-006

TypeScript Type System
Beginner 
loaded: number;
  total: number;
  phase: "metadata" | "tree" | "activity" | "complete";

What

Interface properties without the optional modifier (?), meaning they must be present on any object conforming to this interface

Why

Ensures all progress objects have complete information; prevents undefined/null errors when accessing properties; makes the contract explicit - all three properties are mandatory; simplifies consuming code by eliminating null checks; documents that these are essential properties

How

Properties without '?' after the name are required; TypeScript will error if an object is missing any required property; the absence of '| undefined' in the type means the property cannot be undefined; objects must have all required properties at creation time

Context

All three properties (loaded, total, phase) are required for progress tracking to be meaningful - you always need to know how much is loaded, the total, and what phase you're in

Alternatives

Optional properties (loaded?: number); properties with undefined union (loaded: number | undefined); partial type (Partial<LoadProgress>); separate interfaces for different states; builder pattern for gradual construction; default values in implementation

CONCEPT-008

Design Patterns
Intermediate 
export interface LoadProgress {
  loaded: number;
  total: number;
  phase: "metadata" | "tree" | "activity" | "complete";
}

What

Design pattern for tracking the progress of asynchronous operations using loaded/total counts and phase states

Why

Enables UI progress indicators (progress bars, percentages); provides user feedback during long operations; allows cancellation or retry logic based on progress; helps debug loading issues; enables analytics on loading performance; supports incremental loading strategies

How

Combines numeric progress (loaded/total for percentage calculation) with categorical state (phase for qualitative status); typically updated during async operations and passed to UI components or callbacks; can be used with React state, observables, or event emitters

Context

Designed for tracking multi-phase data loading operations with three distinct phases (metadata, tree, activity) before completion. The loaded/total pattern allows calculating percentage progress within each phase.

Alternatives

Simple percentage number; boolean loading flag; promise-based loading without progress; streaming with progress events; separate state for each phase; progress libraries like nprogress; custom event emitters; RxJS observables with progress
