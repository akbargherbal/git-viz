CONCEPT-023

Beginner

What

Assertion matcher that checks strict equality (===) between actual and expected values, used for primitives and reference equality

Why

toBe uses Object.is() for comparison, making it ideal for primitive values (numbers, strings, booleans, null, undefined). It's more strict than toEqual - it checks that values are the exact same reference for objects. For booleans like true/false, toBe is the appropriate matcher.

How

toBe matcher performs strict equality check using Object.is() algorithm, which is similar to === but handles NaN and -0/+0 differently. For primitives, it compares values directly. For objects, it checks reference equality (same object in memory).

Context

Asserting that isVisible property is exactly the boolean value true. toBe is appropriate here because we're comparing a primitive boolean value, not an object structure.

Alternatives
