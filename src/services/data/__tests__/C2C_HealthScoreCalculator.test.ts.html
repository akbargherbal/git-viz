CONCEPT-001

Testing/Test Framework
Beginner 
import { describe, it, expect } from "vitest";

What

Named imports of core Vitest testing functions: describe for test suites, it for individual tests, and expect for assertions

Why

Vitest is a fast, modern test runner built for Vite projects with Jest-compatible API. It provides better performance than Jest, native ESM support, and seamless integration with Vite's build pipeline. These three functions form the foundation of BDD-style testing.

How

Vitest exports testing utilities as named exports. 'describe' creates test suites (groups of related tests), 'it' defines individual test cases, and 'expect' creates assertions to verify behavior. These are the minimal imports needed for basic testing.

Context

Setting up the test file with Vitest's core testing functions. This file tests the HealthScoreCalculator service, so these imports enable writing structured test suites with assertions.

Alternatives

Jest (import from '@jest/globals' or global); Mocha with Chai; Node's built-in test runner; importing additional Vitest utilities like 'beforeEach', 'afterEach', 'vi' for mocking

Named import using relative path with '../' to access module in parent directory, importing both a class/object and a TypeScript type

Why

Test files are typically organized in __tests__ subdirectories alongside the code they test. The '../' navigates up one level to access the implementation file. This co-location pattern keeps tests close to source code for easier maintenance and discovery.

How

The '../' prefix tells the module resolver to go up one directory level from __tests__ to the parent services/data directory. Imports both the calculator implementation and its input type interface for type-safe test data creation.

Context

Importing the system under test (HealthScoreCalculator) and its input type definition (HealthScoreInputs) from the parent directory. This follows the common pattern of __tests__ folders being siblings to implementation files.
