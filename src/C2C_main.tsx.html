CONCEPT-001

Import/Module Management
Beginner 
import React from "react";

What

Default import of the React namespace from the react package

Why

Required for JSX transformation and accessing React.StrictMode. Even though modern React doesn't require React in scope for JSX (with new JSX transform), it's needed here to access React.StrictMode component. This is a default import because React exports itself as the default export.

How

ES6 module syntax imports the default export from the 'react' package. The imported value is bound to the name 'React' in the current module scope.

Context

Used to access React.StrictMode wrapper component in the render call. This is the standard way to import React when you need to access its namespace properties.

Alternatives

Namespace import 'import * as React from "react"'; named import for specific features 'import { StrictMode } from "react"'; not importing React at all if using new JSX transform and not needing StrictMode

CONCEPT-002

Import/Module Management
Intermediate 
import ReactDOM from "react-dom/client";

What

Default import from the react-dom/client submodule, which contains the modern React 18+ client rendering APIs

Why

React 18 introduced a new client rendering API (createRoot) that enables concurrent features. The /client submodule separates client-side rendering APIs from server-side rendering APIs. This is the modern way to mount React applications and is required for concurrent rendering features like automatic batching, transitions, and Suspense improvements.

How

Imports from a subpath of the react-dom package. The /client path is resolved by the package's exports field in package.json. This provides access to createRoot and hydrateRoot methods.

Context

Used to access the createRoot method for mounting the React application to the DOM. This is the entry point for client-side rendering in React 18+.

Alternatives

Legacy ReactDOM.render from 'react-dom' (deprecated in React 18); ReactDOM from 'react-dom/server' for server-side rendering; third-party rendering solutions

CONCEPT-003

Import/Module Management
Beginner 
import App from "./App";

What

Default import from a local module using relative path notation

Why

Imports the main App component from the same directory. Relative imports are used for local project files. The ./ prefix indicates current directory. No file extension is needed because the bundler (Vite/Webpack) resolves .tsx/.ts/.jsx/.js extensions automatically.

How

Module resolution starts from current file's directory, looks for App.tsx, App.ts, App.jsx, or App.js. The bundler's resolve configuration determines extension priority and resolution rules.

Context

Importing the root App component that serves as the application's main component tree. This component will be rendered inside React.StrictMode.

Alternatives

Path alias import 'import App from "@/App"'; absolute import if configured; named import if App was exported as named export; importing from index file 'import { App } from "./"'

CONCEPT-004

Import/Module Management
Beginner 
import "./index.css";

What

Side-effect import that loads and applies CSS styles without importing any values

Why

Imports global CSS styles that apply to the entire application. This is a side-effect import (no values imported) that tells the bundler to include this CSS file in the build. The styles are injected into the page, typically in the <head> or as a <style> tag. This pattern is used for global styles, CSS resets, or base styles that should apply application-wide.

How

The bundler (Vite/Webpack) processes the CSS file through its CSS loader pipeline, which may include PostCSS, autoprefixer, minification, etc. The processed CSS is either injected via JavaScript or extracted to a separate CSS file depending on build configuration.

Context

Loading global application styles before the app renders. This ensures styles are available when components mount. Placed in entry point so styles load once for entire application.

Alternatives

CSS Modules 'import styles from "./index.module.css"'; CSS-in-JS solutions (styled-components, emotion); importing in HTML file via <link> tag; inline styles; Tailwind or utility-first CSS

CONCEPT-005

React/Client Rendering
Intermediate 
ReactDOM.createRoot(document.getElementById("root")!)

What

React 18+ API that creates a root-level rendering container with concurrent features enabled

Why

Creates a React root that enables concurrent rendering features like automatic batching, startTransition, and Suspense improvements. This is the modern replacement for ReactDOM.render. It returns a root object with render and unmount methods. Concurrent rendering allows React to interrupt rendering work, prioritize updates, and improve responsiveness.

How

Takes a DOM element as argument and returns a Root object. Internally sets up the fiber tree root, enables concurrent mode, and prepares the rendering pipeline. The root manages the entire React tree mounted to that DOM node.

Context

Creating the root rendering container for the entire application, targeting the DOM element with id="root". This is called once at application startup.

Alternatives

Legacy ReactDOM.render (deprecated); ReactDOM.hydrateRoot for SSR hydration; multiple roots for micro-frontends; createRoot with different DOM elements for multiple React apps on same page

CONCEPT-006

Browser APIs/DOM Manipulation
Beginner 
document.getElementById("root")

What

Native browser API that retrieves a DOM element by its id attribute

Why

Provides the target DOM element where React will mount the application. This is the bridge between the HTML page and the React application. The id "root" is a convention for the main application mount point. Returns null if element not found, which is why the non-null assertion is used.

How

Browser's document object provides getElementById method that searches the DOM tree for an element with matching id attribute. Returns HTMLElement or null. This is one of the fastest DOM query methods because ids must be unique.

Context

Selecting the DOM element (typically a <div id="root"></div> in index.html) where the React application will be mounted. This element serves as the container for the entire React component tree.

Alternatives

document.querySelector("#root"); document.querySelector('[id="root"]'); document.body for mounting to body; creating element dynamically with document.createElement

CONCEPT-007

TypeScript/Type System
Intermediate 
document.getElementById("root")!

What

TypeScript operator that asserts a value is not null or undefined, removing those types from the type union

Why

document.getElementById returns 'HTMLElement | null' because the element might not exist. The non-null assertion (!) tells TypeScript "I know this will not be null at runtime" and removes null from the type, making it just 'HTMLElement'. This is used when the developer has external knowledge that the element exists (e.g., it's in the HTML file). Without this, TypeScript would error because createRoot expects HTMLElement, not HTMLElement | null.

How

Postfix ! operator performs a type assertion that removes null and undefined from the type union. This is a compile-time only operation - no runtime code is generated. If the value is actually null at runtime, it will cause a runtime error.

Context

Asserting that the "root" element exists in the HTML. This is safe because the index.html file is expected to contain <div id="root"></div>. If the element doesn't exist, the app will fail to mount with a clear error.

Alternatives

Optional chaining with fallback 'document.getElementById("root") ?? document.body'; type guard with if statement; using as HTMLElement type assertion; creating element if not found; disabling strictNullChecks in tsconfig

CONCEPT-008

JavaScript/API Design
Beginner 
ReactDOM.createRoot(document.getElementById("root")!).render(...)

What

Calling the render method immediately on the Root object returned by createRoot

Why

Fluent API pattern that allows chaining method calls. createRoot returns a Root object with a render method, so we can call render immediately without storing the root in a variable. This is concise for one-time rendering. If you need to call render multiple times or unmount later, you'd store the root in a variable.

How

createRoot returns an object, and the .render() method is called on that returned object. JavaScript evaluates left-to-right, so createRoot executes first, returns Root object, then .render() is called on that object.

Context

Immediately rendering the application after creating the root. This is the standard pattern for entry point files where you create and render in one statement.

Alternatives

Store root in variable: 'const root = ReactDOM.createRoot(...); root.render(...)'; separate statements for clarity; storing root for later unmounting or re-rendering

CONCEPT-009

React/Development Tools
Intermediate 
<React.StrictMode>
    <App />
  </React.StrictMode>

What

React wrapper component that enables additional development-time checks and warnings for its descendants

Why

Activates extra checks in development mode to help identify potential problems: (1) Warns about deprecated lifecycle methods; (2) Warns about legacy string ref API usage; (3) Warns about deprecated findDOMNode usage; (4) Detects unexpected side effects by double-invoking certain functions; (5) Detects legacy context API; (6) Ensures reusable state. StrictMode has no effect in production builds. It helps catch bugs early and prepare for future React features.

How

Wraps child components and enables additional checks during rendering. In development, React intentionally double-invokes certain functions (like function components, useState initializers, useEffect callbacks) to help detect side effects. This is a component that renders its children without adding DOM nodes.

Context

Wrapping the entire App component to enable strict mode checks for the whole application. This is best practice for new React applications and helps maintain code quality.

Alternatives

No StrictMode wrapper (not recommended); wrapping only specific subtrees; using React DevTools for debugging instead; custom development-only wrappers

CONCEPT-010

React/JSX Syntax
Beginner 
<App />

What

JSX syntax for rendering a component without children using self-closing tag notation

Why

Concise syntax for components that don't need children. Equivalent to <App></App> but more readable and conventional when no children are needed. This is the standard way to render components without content between opening and closing tags.

How

JSX transpiles to React.createElement(App, null) - creating an element of type App with no props and no children. The /> syntax is borrowed from XML/HTML self-closing tags.

Context

Rendering the root App component without passing any children. The App component will render its own internal component tree.

Alternatives

Opening and closing tags '<App></App>'; passing children '<App>content</App>'; passing props '<App prop={value} />'

CONCEPT-011

React/Component Patterns
Beginner 
<React.StrictMode>
    <App />
  </React.StrictMode>

What

Nesting React components within other components using JSX syntax

Why

Fundamental React pattern for building component trees. Parent components wrap child components to provide context, behavior, or structure. Here, StrictMode wraps App to provide development-time checks. This composition pattern is how React applications are structured - small components compose into larger ones.

How

JSX allows nesting elements just like HTML. The parent component (StrictMode) receives the child component (App) as its children prop. React builds a tree structure where each component can render other components.

Context

Composing the application by wrapping the App component with StrictMode. This creates a component tree where StrictMode is the root and App is its child.

Alternatives

Render props pattern; Higher-Order Components (HOCs); passing components as props; using Context for cross-cutting concerns; compound component pattern

CONCEPT-012

JavaScript/Code Style
Beginner 
ReactDOM.createRoot(document.getElementById("root")!).render(
  <React.StrictMode>
    <App />
  </React.StrictMode>,
);

What

Optional trailing comma after the last argument in a function call

Why

Modern JavaScript style convention that provides several benefits: (1) Cleaner git diffs when adding/removing arguments - only the changed line shows in diff; (2) Easier to reorder arguments; (3) Prevents errors when adding new arguments; (4) Consistent with array and object literal trailing commas. This is allowed in ES2017+ and is a common Prettier/ESLint convention.

How

JavaScript parser allows optional trailing comma in function calls, array literals, and object literals. The comma is simply ignored by the parser but preserved by formatters for the benefits above.

Context

Following modern JavaScript style conventions. The trailing comma after the JSX argument makes it easier to add additional arguments to render() in the future without modifying this line.

Alternatives

No trailing comma (older style); ESLint/Prettier rules to enforce or forbid trailing commas; different style guides

CONCEPT-013

Architecture/Application Structure
Intermediate 
// src/main.tsx
import React from "react";
import ReactDOM from "react-dom/client";
import App from "./App";
import "./index.css";

ReactDOM.createRoot(document.getElementById("root")!).render(
  <React.StrictMode>
    <App />
  </React.StrictMode>,
);

What

Standard pattern for React application entry point file that bootstraps the application

Why

Separates application bootstrapping from application logic. This file's sole responsibility is to: (1) Import necessary dependencies; (2) Load global styles; (3) Mount the React application to the DOM. This separation of concerns makes the codebase more maintainable. The App component contains the actual application logic, while main.tsx just handles the mounting process.

How

Build tools (Vite, Webpack) are configured to use this file as the entry point. The bundler starts here and follows all imports to build the dependency graph. This file is executed when the application loads in the browser.

Context

This is the application's entry point, referenced in index.html via <script type="module" src="/src/main.tsx"></script> or similar. It's the first JavaScript file executed when the app loads.

Alternatives

index.tsx as entry point name; mounting multiple React apps; server-side rendering entry point; different file structure for micro-frontends

CONCEPT-014

TypeScript/File Types
Beginner 
// src/main.tsx

What

File extension indicating TypeScript file with JSX syntax support

Why

.tsx extension tells TypeScript compiler and build tools that this file contains both TypeScript and JSX syntax. This is required for files that use JSX - .ts files cannot contain JSX. The extension enables proper parsing and type checking of both TypeScript types and JSX elements.

How

TypeScript compiler recognizes .tsx extension and enables JSX parsing mode. Build tools (Vite, Webpack) use this extension to determine which loaders/transformers to apply. The file is processed through TypeScript compiler and JSX transformer.

Context

This entry point file uses .tsx because it contains JSX syntax (<React.StrictMode>, <App />). Even though it's mostly imports and one render call, the JSX requires .tsx extension.

Alternatives

.ts for TypeScript without JSX; .jsx for JavaScript with JSX; .js for plain JavaScript; .mts/.cts for ES modules/CommonJS TypeScript

Comment at the top of the file indicating its location in the project structure

Why

Helps developers quickly identify the file's location when viewing code snippets, in search results, or when multiple files are open. Particularly useful in large codebases, during code reviews, or when sharing code snippets. Some teams enforce this as a convention for better code navigation.

How

Single-line comment using // syntax placed at the very top of the file. The path is typically relative to the project root.
