interface PluginMetadata {

  version: string;

What

TypeScript interface defining the shape of an object with specific property names and types

Why

Provides compile-time type safety by defining a contract for what properties an object must have. Interfaces enable IDE autocomplete, catch type errors before runtime, document expected object structure, and can be extended or implemented by other types/classes.

How

Uses 'interface' keyword followed by name and curly braces containing property signatures. Each property has a name, colon, and type annotation. Semicolons separate properties (optional but conventional). TypeScript compiler uses this for type checking but removes it from compiled JavaScript.

Context

Defines the structure for plugin metadata objects, specifying that plugins must have an id, name, description, version (all strings), and a numeric priority value

Alternatives

Type alias 'type PluginMetadata = { ... }'; class with properties; inline object type; Record utility type; index signature; using 'any' or no typing (loses type safety)

What

Generic Set type parameterized with string, representing a collection of unique string values

Why

Set provides O(1) lookup time for checking membership, automatically handles uniqueness (no duplicates), and is more semantically correct than arrays for representing collections where order doesn't matter and uniqueness is required. The generic parameter ensures type safety for the values stored in the Set.

How

Uses TypeScript's generic syntax 'Set<T>' where T is the type of elements. Set is a built-in JavaScript/TypeScript type. The angle brackets contain the type parameter, ensuring all elements in the Set must be strings. TypeScript provides type checking for Set operations like add(), has(), delete().

Context

Used for four filter properties in FilterState interface: authors, directories, fileTypes, and eventTypes. These represent collections of unique filter values where duplicates should be automatically prevented and fast lookup is needed.

Alternatives

Array of strings 'string[]' (allows duplicates, slower lookup); Record<string, boolean> for lookup table; Map<string, any> if additional data needed; plain object with string keys; custom class wrapping Set

What

Inline object type definition specifying an object with two Date properties, combined with a union type allowing null

CONCEPT-011

TypeScript Type System
Intermediate 
timeRange: { start: Date; end: Date } | null;

What

Union type combining an object type with null, allowing the property to be either the object or null

Why

Represents optional/nullable data in a type-safe way. The union with null explicitly documents that this value may not be present, forcing developers to handle the null case. This is more explicit than using undefined and aligns with the convention that null represents intentional absence of a value.

How

Uses the pipe operator '|' to create a union type between the object type and null. TypeScript's type system requires checking for null before accessing properties (with strictNullChecks enabled), preventing null reference errors. Developers must use null checks or optional chaining to safely access the value.

Context

Makes the timeRange filter optional in FilterState. When no time filtering is applied, timeRange is null; when time filtering is active, it contains the start and end dates.

Alternatives

Optional property 'timeRange?: { start: Date; end: Date }' (undefined instead of null); separate boolean flag 'hasTimeRange'; using undefined explicitly '| undefined'; making start/end optional within object; using empty object {} to represent no filter

Tags

typescript union-type null nullable optional-data type-safety

What

PascalCase naming convention for interfaces, using descriptive compound nouns

Why

PascalCase is the TypeScript/JavaScript convention for types and classes, making them visually distinct from variables and functions (camelCase). Descriptive names clearly communicate the purpose of each interface. Compound nouns (Plugin + Metadata, Filter + State, Export + Options) create self-documenting type names.

How

Each word in the interface name starts with a capital letter, with no separators between words. Names are chosen to be descriptive nouns or noun phrases that clearly indicate what the interface represents.

Context

Three interfaces follow this pattern: PluginMetadata (data about a plugin), FilterState (state of filters), ExportOptions (options for exporting). Each name clearly indicates its purpose.

Alternatives

Prefixing with 'I' (IPluginMetadata - older convention); snake_case; camelCase; all lowercase; using suffixes like 'Type' or 'Interface'; shorter abbreviated names
