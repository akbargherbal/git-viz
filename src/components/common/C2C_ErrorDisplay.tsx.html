CONCEPT-005

TypeScript/Type System
Intermediate 
onDismiss?: () => void;

What

Optional prop typed as a function that takes no parameters and returns void, indicated by the ? marker

Why

Making onDismiss optional allows the component to be used in contexts where dismissing isn't needed (e.g., critical errors that shouldn't be dismissed). The void return type indicates this is a side-effect function not expected to return a value. This follows React's event handler naming convention (on* prefix).

How

The '?' makes the property optional - it can be undefined. The '() => void' is a function signature type: zero parameters, returns nothing. TypeScript enforces that if provided, onDismiss must be a function matching this signature.

Context

Callback function to be invoked when the user clicks the dismiss (X) button. If not provided, the dismiss button won't be rendered. This allows parent components to control dismissal behavior.

Alternatives

Required callback with default no-op 'onDismiss: () => void' with default value; more specific signature like 'onDismiss: (errorId: string) => void' to pass context; using MouseEvent type '(e: MouseEvent) => void' to access event object

CONCEPT-020

React/Conditional Rendering
Intermediate 
{onDismiss && (
            <button
              onClick={onDismiss}
              className="text-red-400 hover:text-red-300"
            >
              <X size={20} />
            </button>
          )}

What

Conditional rendering using JavaScript logical AND (&&) operator to render button only if onDismiss prop exists

Why

This pattern allows the dismiss button to be optional. If onDismiss is undefined/null/false, the button won't render. This is more concise than ternary operators for simple show/hide logic. It makes the component flexible - usable with or without dismiss functionality.

How

JavaScript's && operator short-circuits: if left side is falsy, it returns that value and doesn't evaluate the right side. In JSX, falsy values (except 0) render nothing. If onDismiss is truthy, React renders the button. If falsy, nothing renders.

Context

Only rendering the close/dismiss button when the parent component provides an onDismiss callback. This allows the error display to be used in contexts where dismissing isn't appropriate.

Alternatives

Ternary operator 'onDismiss ? <button>...</button> : null'; separate conditional 'if (onDismiss) return <button>'; always render button but disable it; using optional chaining 'onDismiss?.() && <button>'

Tags

react conditional-rendering logical-and jsx optional-ui

What

Pattern where parent component passes callback function as prop to child component for handling events

Why

This pattern enables child-to-parent communication in React's unidirectional data flow. The child (ErrorDisplay) can trigger actions in the parent without knowing implementation details. This maintains encapsulation and makes components reusable - different parents can provide different dismiss behaviors.

How

Parent passes function reference as prop. Child calls that function when event occurs (button click). The function executes in parent's context, allowing parent to update state, make API calls, etc. The child just triggers the callback.

Context

The onDismiss callback allows the parent component to control what happens when the error is dismissed - maybe remove it from state, log it, navigate away, etc. ErrorDisplay doesn't need to know these details.

Alternatives
