What

Creates a new Promise using the Promise constructor with an executor function that controls when the Promise resolves

Why

Allows custom control over Promise resolution timing. Wraps callback-based APIs (like setTimeout) in Promise interface. Enables async/await usage with timer-based operations. Provides a way to defer execution to the next event loop tick.

The Promise constructor takes an executor function with resolve and reject parameters. The executor runs immediately and can call resolve() to fulfill the Promise or reject() to reject it. Here, setTimeout calls resolve after 0ms.

CONCEPT-023

Async Patterns/Event Loop
Advanced 
setTimeout(resolve, 0)

What

Schedules a callback to run after the current call stack clears, using setTimeout with 0 millisecond delay

Why

Defers execution to the next event loop tick, allowing pending async operations to complete. Useful in tests to wait for state updates, DOM changes, or Promise resolutions. The 0ms delay doesn't mean immediate execution—it means "as soon as possible after current code finishes".

How

setTimeout adds the callback to the task queue. Even with 0ms delay, it won't execute until the current call stack is empty and the event loop processes the task queue. This creates a minimal async delay.

Context

Creates a utility that waits for one event loop tick, allowing tests to wait for async operations like state updates or DOM rendering to complete before making assertions.

Alternatives

setImmediate (Node.js, more explicit); queueMicrotask (runs before setTimeout); Promise.resolve().then(); requestAnimationFrame (for DOM updates); actual delay with setTimeout(resolve, 100)

Tags

settimeout event-loop async testing zero-delay

CONCEPT-025

JavaScript/Closures
Intermediate 
export const createMockFetch = (data: any) => {
  return vi.fn(() =>
    Promise.resolve({
      ok: true,
      json: () => Promise.resolve(data),
    }),
  ) as any;
};

What

Inner functions (the vi.fn callback and json method) capture and reference the 'data' parameter from the outer function's scope

Why

Allows the mock functions to access the data parameter even after createMockFetch returns. Creates a persistent reference to the data for the lifetime of the mock. Essential for the mock to return the correct data when called. Demonstrates JavaScript's closure mechanism.

How

JavaScript closures allow inner functions to access variables from outer function scopes. When createMockFetch returns, the 'data' parameter remains accessible to the returned mock function and its json method because they close over it.

Context

The mock fetch function and its json method both need access to the 'data' parameter to return it when called. Closure ensures this data remains available throughout the mock's lifetime.

Alternatives

Passing data as parameter to mock function; using class with instance variable; global variable (bad practice); binding data to function; using object with data property
