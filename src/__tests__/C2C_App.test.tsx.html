CONCEPT-001

Testing/Best Practices
Intermediate 
// Mocks must be defined before imports to avoid hoisting issues in some environments

What

Explanatory comment documenting the requirement to define mocks before other imports

Why

JavaScript module hoisting can cause issues where imports are processed before mock definitions, leading to the real modules being loaded instead of mocks. This comment documents the intentional ordering to prevent test failures.

How

By placing this comment at the top, it serves as documentation for developers who might be tempted to reorganize imports, explaining why mocks must come first in the file structure.

Context

Used at the very beginning of the test file to explain the non-standard import ordering where vi.mock() calls precede all other imports

Alternatives

Could use ESLint disable comments; could use a different test framework with different hoisting behavior; could restructure tests to avoid this requirement; could use factory functions instead of top-level mocks
