CONCEPT-001

Import/Module Management
Intermediate 
import "@testing-library/jest-dom";

What

Import statement without any bindings that executes module code for its side effects only

Why

The @testing-library/jest-dom package extends Jest/Vitest matchers with DOM-specific assertions (toBeInTheDocument, toHaveClass, etc.). Importing it registers these custom matchers globally without needing to reference any exports. This is a common pattern for test setup files that need to augment the testing framework.

How

ES6 modules execute their top-level code when imported. Side-effect imports run the module's initialization code without binding any exports to variables. The module's code modifies global state (in this case, adding custom matchers to the test framework).

Context

Used at the top of the test setup file to ensure all test files have access to enhanced DOM matchers like expect(element).toBeVisible() without explicit imports in each test file.

Alternatives

Explicit import and setup in each test file; using a test framework plugin system; importing and calling a setup function; using global setup in test configuration file
